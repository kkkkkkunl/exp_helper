# Proposal

## Why

项目已有实验记录、库存事务、项目技能库、结果与归档等 v3 能力，但 OpenSpec 尚无主规格，已完成工作与待实现需求缺少统一边界。需要形成覆盖整个实验工作流的方案，在保留已有实现的基础上补齐阶段模板、样品继承、交互记录及日历闭环，而非仅为本次新增功能另起孤立计划。

## What Changes

- 建立全项目行为基线，覆盖安装、按需路由、记录与附件、样品库存、结果与分析、汇报和归档；已有实现及已完成文档以证据登记为完成，不重复开发。
- 增加通用阶段模板规范：阶段、步骤、入口、暂停点、继续条件、输入产物和字段类型；实现模板内容与版本固定及旧模板兼容。
- 增加逐样品进度、同一实验续接、新实验继承旧样品、阶段产物来源、失败重做和事实更正的影响追溯。
- 按模板集中提示待填信息，接受自由文本和多步骤输入；确认阶段或暂停才写入对应事实，普通回答保持会话草稿。
- **BREAKING（行为修订）**：废除“模板默认值自动视为实际执行”，旧模板也须确认所列操作参数，实测结果必须有实际来源。
- 输入“暂停”将已执行部分作为本次完成阶段保存，剩余步骤转日历，未做步骤仍保持未执行。
- 明确提交最终实验结果后自动整理、结束实验并在检查通过后自动归档；检查未通过时保留状态，后续条件满足后继续。增加实验级 `important`，与结果精选独立。
- 首次安装由宿主会话询问目标日历并安装或连接对应插件／MCP；每个后续阶段一条事项，补问缺失排期，更新原事项并保留用户手工排期。
- 同步说明与状态迁移，明确实验自动保存／归档授权与项目 OpenSpec 历史、手动 Git 提交的边界。

## Capabilities

### New Capabilities

当前 `openspec list --specs` 返回无规格。以下均为首次纳入 OpenSpec 的能力：其中已有功能属于规格基线登记，不意味着其代码尚未完成；新增和缺口见 design.md 与 tasks.md。

- `project-foundation`: 项目安装、配置、项目内技能索引、按需路由、范围校验和仓库文件约定。
- `experiment-records`: 稳定实验身份、事实记录、显式保存、人工修改保护及原始附件追溯。
- `stage-templates`: 阶段模板、参数确认、内容版本固定、逐样品进度、暂停续接、分支和阶段尝试。
- `sample-inventory`: 样品台账、单位与数量、授权事务、幂等恢复以及阶段产物和跨实验来源。
- `results-analysis-reporting`: 已有结果整理、按需分析、结果版本及精选、局部失效和科研汇报规则。
- `lifecycle-archiving`: 结果完成属性、执行结束、最终结果指令、自动归档及实验重要标记。
- `calendar-followup`: 安装时日历接入、后续阶段排期、事项更新、防重复和失败恢复。

### Modified Capabilities

无既有 OpenSpec 主规格可修改；上述行为首次定义为 ADDED requirements。旧说明与实际代码的冲突在设计中列明，不能因已有说明而把缺失实现勾选完成。

## Impact

- 保留并扩展 `experiment-workflow/scripts/{install,project,skill_store,workflow,allocate_id,inventory,results,archive,_common,_record_metadata}.py` 的职责与兼容入口；阶段、模板及日历协调建议拆为独立模块。
- 更新 `experiment-workflow/SKILL.md`、`references/`、`assets/`、项目配置模板及 `openspec/config.yaml`；设计和说明继续存放 `docs/`。
- 状态与样品元信息增加阶段、尝试、来源、确认、待归档及远端事项映射，需兼容既有 v3 记录、样品和自定义属性。
- 日历依赖所选宿主插件／MCP 和用户连接授权；通用协调不要求一次实现所有服务的独立 SDK，未知具体服务在首次安装时选定并核查能力。
- qPCR 只提供无真实参数的结构示例；不新增实际实验规程、专业分析算法、后台监听服务或独立 PPT 渲染引擎。
- 已有测试文件和历史测试日志保留为证据；提案阶段只核查源码与文档，不以历史测试日志替代新验证；本轮实施已执行新增验收和基线回归，结果见 docs/v4-实施说明与验证.md。
