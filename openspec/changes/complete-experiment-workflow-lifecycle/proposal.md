# Proposal

## Why

项目已有实验记录、库存事务、项目技能库、结果与归档等 v3 能力，但 OpenSpec 尚无主规格，已完成工作与待实现需求缺少统一边界。需要形成覆盖整个实验工作流的方案，在保留已有实现的基础上补齐阶段模板、样品继承、交互记录及日历闭环，而非仅为本次新增功能另起孤立计划。

阶段与日历能力已完成本变更原有实施；本次进一步将实验级 skill 的启动前移到实验及方案确定时，使上样计算能在操作前展示、经确认进入记录并保留修改历史。新增范围依据 [实验启动与上样计算设计方案](../../../docs/实验启动与上样计算设计方案.md)及三轮已确认决定，任务状态与旧版验证证据分开维护。

在上述已完成范围之后，新增一轮规划修订依据 [`$exp` 入口与实验记录模板优化方案](../../../docs/exp入口与实验记录模板优化方案.md)：在对话中以 `$exp` 显式进入主工作流，统一正式记录的模板结构，使用问答框核对当前步骤缺项与冲突，并将取值过程留在内部证据而非拼入正文。该轮已按用户明确调用的 apply 实施；新增任务的证据独立记录在 [v6 验证报告](../../../docs/v6-验证报告.md)，不沿用此前完成勾选。

## What Changes

- 建立全项目行为基线，覆盖安装、按需路由、记录与附件、样品库存、结果与分析、汇报和归档；已有实现及已完成文档以证据登记为完成，不重复开发。
- 增加通用阶段模板规范：阶段、步骤、入口、暂停点、继续条件、输入产物和字段类型；实现模板内容与版本固定及旧模板兼容。
- 增加逐样品进度、同一实验续接、新实验继承旧样品、阶段产物来源、失败重做和事实更正的影响追溯。
- 按模板集中提示待填信息，接受自由文本和多步骤输入；确认阶段或暂停才写入对应事实，普通回答保持会话草稿。
- **BREAKING（行为修订）**：废除“模板默认值自动视为实际执行”，旧模板也须确认所列操作参数，实测结果必须有实际来源。
- 输入“暂停”将已执行部分作为本次完成阶段保存，剩余步骤转日历，未做步骤仍保持未执行。
- 明确提交最终实验结果后自动整理、结束实验并在检查通过后自动归档；检查未通过时保留状态，后续条件满足后继续。增加实验级 `important`，与结果精选独立。
- 首次安装由宿主会话询问目标日历并安装或连接对应插件／MCP；每个后续阶段一条事项，补问缺失排期，更新原事项并保留用户手工排期。
- 同步说明与状态迁移，明确实验自动保存／归档授权与项目 OpenSpec 历史、手动 Git 提交的边界。
- **BREAKING（启动规则修订）**：实验类型及模板或方案确定、用户明确开始或继续实验后即加载对应实验级 skill，不再等到结果计算请求才加载；按当前步骤执行，不因加载而自动开展结果分析。
- 以用户明确指定、模板绑定、实验类型匹配的优先级定位技能，缺失或歧义仅暂停相关计算，记录及无关样品可独立继续；按需读取目标内容，不扫描全库正文。
- 模板提供流程、输入和记录字段，计算公式、执行及校验统一归 skill。计算量立即在会话展示，经阶段确认或暂停保存写入输入、单位、依据及结果；与实际量和库存消耗分开。
- 首次保存固定实际使用的技能版本或内容依据；续接沿用，明确升级后重算受影响部分。已保存内容更正保留完整旧记录，项目根 `history/` 按实验编号与北京时间修改时刻命名，并关联对应实验归档。
- **范围暂缓**：本次不修改现有 qPCR 模板，不迁移其已有计算，不交付具体 qPCR 专业技能；旧模板计算不作为新工作流缺失 skill 时的自动替代。
- **新增规划范围**：提供仓库内名为 `exp` 的薄入口；进入主工作流后仍按既有实验确定条件激活子技能，保留既有主技能名称供旧调用兼容。
- **新增规划范围**：新正式记录以记录模板为结构来源，保存前校验必需章节、层级与顺序；允许正文留空及对应章节内补充小节。旧记录保持原格式，只有明确要求时迁移。
- **新增规划范围**：当前步骤的阻断性缺项与冲突优先通过问答框集中核对，可靠候选供选择，其余开放输入；正式记录只写确认值，必要的样本、模板和计算关联仍保留。相对时间先确认候选北京时间，再以 `HH:mm` 写入正文，取值及估计依据保存在内部状态。
- **本轮边界**：不修改现有 `cell-qpcr`、`qpcr-ddcq` 或细胞 qPCR 方法模板，不独立拆出细胞培养技能；既有已完成任务及验证证据不作为上述新增范围的完成证明。

## Capabilities

### New Capabilities

当前 `openspec list --specs` 返回无规格。以下均为首次纳入 OpenSpec 的能力：其中已有功能属于规格基线登记，不意味着其代码尚未完成；新增和缺口见 design.md 与 tasks.md。

- `project-foundation`: 项目安装、配置、项目内技能索引、实验确定时按优先级加载技能、范围校验和仓库文件约定。
- `experiment-records`: 稳定实验身份、事实记录、计算来源与实际用量分离、显式保存、项目级 history、人工修改保护及原始附件追溯。
- `stage-templates`: 阶段模板、技能绑定、模板不承担计算的职责边界、参数确认、内容版本固定、逐样品进度、暂停续接、分支和阶段尝试。
- `sample-inventory`: 样品台账、单位与数量、授权事务、计算不代表实际扣账、幂等恢复以及阶段产物和跨实验来源。
- `results-analysis-reporting`: 实验级技能计算、技能依据固定与显式升级、已有结果整理、按需分析、结果版本及精选、局部失效和科研汇报规则。
- `lifecycle-archiving`: 结果完成属性、执行结束、最终结果指令、自动归档、实验重要标记及项目级历史的归档关联。
- `calendar-followup`: 安装时日历接入、后续阶段排期、事项更新、防重复和失败恢复。

### Modified Capabilities

无既有 OpenSpec 主规格可修改；上述行为首次定义为 ADDED requirements。旧说明与实际代码的冲突在设计中列明，不能因已有说明而把缺失实现勾选完成。

## Impact

- 保留并扩展 `experiment-workflow/scripts/{install,project,skill_store,workflow,allocate_id,inventory,results,archive,_common,_record_metadata}.py` 的职责与兼容入口；阶段、模板及日历协调建议拆为独立模块。
- 更新 `experiment-workflow/SKILL.md`、`references/`、`assets/`、项目配置模板及 `openspec/config.yaml`；设计和说明继续存放 `docs/`。
- 状态与样品元信息增加阶段、尝试、来源、确认、待归档及远端事项映射，需兼容既有 v3 记录、样品和自定义属性。
- 增量扩展技能绑定、计算证据及技能内容依据，覆盖记录正文和受管属性修改的历史留存、事务恢复与归档清单；保持旧状态可读，不从无依据的历史补造已执行计算。
- 日历依赖所选宿主插件／MCP 和用户连接授权；通用协调不要求一次实现所有服务的独立 SDK，未知具体服务在首次安装时选定并核查能力。
- 本次不修改现有 `experiment-workflow/assets/qPCR.md`，不迁移其公式或可执行计算块，也不新增真实实验规程、具体 qPCR 专业技能、后台监听服务或独立 PPT 渲染引擎。通用能力使用临时测试技能验收。
- 实验记录版本使用项目根 `history/`；OpenSpec 变更历史仍遵循 `hisotry/`，不混同或重命名，不因实验保存自动归档 OpenSpec 变更。
- 原有实施的验收和基线回归见 docs/v4-实施说明与验证.md，仅证明旧版任务。用户后续已明确调用 apply，增量实施与新验证结果另见 docs/v5-实施说明与验证.md，不复用旧日志宣称增量已完成。
- 新一轮入口、问答与记录结构改动的实施及验证见 v6 报告；宿主真实问答界面能力仍以实际可用工具为边界，不据此前 75 项完成状态宣称新增范围已经交付。
