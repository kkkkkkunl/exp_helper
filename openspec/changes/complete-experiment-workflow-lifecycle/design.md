# Design

实施注记：本文件保留提案时的基线与设计依据；原有 57 项任务的实现状态见 tasks.md 第 1—9 组及 [v4 实施报告](../../../docs/v4-实施说明与验证.md)。本次实验技能启动与计算历史的增量见 D9—D13、tasks.md 第 10—13 组及 [v5 实施报告](../../../docs/v5-实施说明与验证.md)。下文早期缺口表不代表当前仍未完成。

## Context

动机和能力边界见 [proposal.md](proposal.md)。目标项目是本仓库的 `experiment-workflow/`；OpenSpec 根已解析为 `F:/experiment-workflow`，主规格为空。本变更首次记录完整系统契约，ADDED 不等于所有实现均为新开发。

最新用户决定来源为 [合并设计](../../../docs/阶段式实验与交互记录设计方案.md)、[访谈](../../../docs/阶段式实验与交互记录设计访谈.md)及 ADR 0003—0007。暂停、自动实验归档和日历规则采用后续修订，不重新采用早期访谈建议。

实验技能启动、上样计算及历史规则采用 [新增完整方案](../../../docs/实验启动与上样计算设计方案.md)、[三轮访谈](../../../docs/实验启动与上样计算设计访谈.md) Q1—Q10 及 [ADR 0009](../../../docs/adr/0009-experiment-skill-lifecycle-and-calculation-records.md)。Q11 的具体 qPCR 模板迁移被明确暂缓；用户后续已明确调用 OpenSpec apply 授权通用增量实施。

## Goals / Non-Goals

**Goals:**
- 复用 B01—B15，以小模块扩展现有脚本，形成从配置、记录到结果归档和日历续接的完整契约。
- 使每项待做任务均能对应具体规格、代码区域和验收场景；完成基线独立展示。
- 兼容已有 v3 记录、样品、结果版本和人工内容，明确升级后的参数确认行为。
- 将实验级技能定位、计算信息及项目级记录历史纳入同一生命周期，计算提前到上样前，保存与实际操作边界保持独立。

**Non-Goals:**
- 不编造 qPCR 操作规程、暂停条件或专业算法；结构示例不携带真实实验默认值。
- 不建设独立 Web 产品、全局共享分析库、常驻后台服务或全服务日历 SDK。
- 不重做已存在的库存引擎、结果版本存储或单独开发 PPT 渲染引擎。
- 不在 propose 阶段修改代码、同步主规格、归档变更或执行 Git 提交。
- 本次增量不修改现有 qPCR 模板及其历史快照，不迁移其计算，不新增或完成具体 qPCR 专业技能；使用测试技能验证通用契约。

## Decisions

### D1：以当前能力建立规格基线，新增需求作为增量

七个能力规格同时描述已有行为及目标增量；tasks.md 第 1—9 组保留原 57 项已完成证据，第 10—13 组列此次新增待办。完成项的证据粒度必须窄于新能力边界，旧版验收不能证明新增计算或 history 能力。

替代方案是只写阶段和日历，会遗漏本项目其他契约；或将所有任务重列为未完成，会违背用户要求并重复既有工作。报告规则仅标“已交付规则”，不冒称已有独立生成引擎。

### D2：结构化阶段模板，保留普通模板

新增 `scripts/stage_templates.py` 及 `references/stage-template-rules.md`，阶段模板使用现有 YAML 子集，配置区分普通和阶段格式。阶段定义包括 id、steps、输入材料类型、产物、入口、后继、暂停点、继续要求；字段包括 id、类型、单位、必填性、允许未测定／不适用及默认参数来源。

静态后继须引用有效标识，禁止无法终止的静态循环；真实重做通过尝试记录表达。验证阶段及字段唯一性、必需信息、合法引用和声明入口，返回明确错误，不从普通 Markdown 自动推断完整阶段图。

保存新实验时将所选模板原文、配置版本、内容哈希及来源相对路径存为内部只读快照；恢复依哈希读取快照。升级通过显式映射和确认生成新快照引用，旧快照保留。相比只存版本号，内容快照能防止同版本文件被改写后影响旧实验。

操作参数的来源状态区分参考预设、用户输入和明确确认；实测结果只能来自实际输入。默认值不自动写为执行值，普通模板同样适用。

### D3：状态升级，分开本次阶段收尾与实际步骤

内部 workflow 状态升级为版本 4，保留 inputs、record、analysis、result_tasks、inventory、record_round 和 archived 等旧字段，增加用户提供的实际实验日期用于列表排序（旧记录未知日期不从编号推断），并增加：

| 信息组 | 内容 | 约束 |
|---|---|---|
| template_snapshot | 模板名、格式、版本、来源、快照路径及哈希 | 实验创建后固定，升级显式 |
| stage_progress | 每个样品的阶段、步骤及输入输出 | 未执行、已执行和待补信息分开 |
| attempts / segments | 真实阶段尝试、暂停关闭的已执行片段及恢复位置 | 重做新增尝试；暂停只关闭已做部分 |
| confirmations | 用户请求、确认范围、预览内容哈希及库存清单指纹 | 不把事后变化并入旧授权 |
| execution / archive_request | 最终结果范围、结束状态、归档授权及待处理原因 | 与整理和分析状态独立 |
| followups | 稳定待办标识、阶段、剩余步骤、日历映射和同步状态 | 元信息用于恢复，不是第二份用户待办文档 |
| corrections / review_links | 原依据、更正依据及受影响关系 | 已发生操作保留，相关工作待复核 |

界面按用户要求显示“本次阶段已完成”，同时显示剩余待办；模板步骤仍是事实来源。一个暂停片段完成不能使原模板所有步骤或对应剩余日历事项完成。多样品按输入实例分别推进，相同步骤可在会话集中填写。

替代方案是复用一个 completed 布尔值表示阶段、结束和结果，容易把未做步骤标完；现有 completed 继续专用于结果整理。

### D4：预览与写入分离，保存动作协调既有事务

新增 `scripts/stage_workflow.py` 处理阶段预览、确认、暂停、恢复和最终结果动作，保留原 workflow CLI 的显式调用语义。普通回答只在宿主会话中收集，不调用会立即写文件的 `start`、编号分配或库存 plan；用户明确确认后才分配新编号、持久化原始输入及阶段状态。

预览汇总必须先于阶段确认。库存计划若需脚本预计算，未获保存授权的预览使用无写入计算入口；持久化及确认绑定具体清单内容和台账快照。阶段保存可先完成，未知或待确认库存单独等待，不能因暂停指令而跳过清单授权。

每个保存动作有稳定 action_id 和阶段尝试关联，记录保存、库存核查、日历同步与归档分别记成功收据或待处理状态。采用当前原子文件替换与锁；必要时扩展本地动作日志，恢复时从未完成环节继续，不能再次写同一记录轮次或重复扣账。锁顺序统一为工作流、库存、归档；远端日历调用期间不持有本地锁。

这样复用已有可恢复库存事务，而不是声称记录文件、库存和远端日历可跨系统原子提交。直接显式调用旧 CLI 仍是用户要求写入，不等于会话每个回答都自动落盘。

### D5：材料转化来源与库存调整分开建模

样品在保留 parent（分装）、sources（混合）和 experiments 的基础上新增材料类型及 produced_by（实验、阶段、尝试、输入样品引用）。新材料仍由已有基础编号分配器分配独立编号，不能伪装成分装子管。

材料转化以输入实际使用事件和产物实际入库事件共同关联阶段操作，进入既有计划／提交框架；不同材料间不强加分装的体积守恒或自动浓度继承。产物编号可被保留为待补数量，但不能在无实际依据时入库或继续扣减。

浓度信息保留值、单位、对象及实测／计算依据，未知、未测定和不适用明确区分。现有台账已有 concentrations，但库存 commit 主要更新余额、单位和位置；阶段产物或浓度更正的受控写入需纳入计划指纹与事务，不以自动继承或台账外另存一套方式绕过确认。未登记试剂继续只写方法。

库存更正新增显式调整入口和事件类型，绑定原事件或来源依据、调整理由及确认清单，使用新 event_id 及同一快照／事务引擎。原事件内容不改写。跨实验依赖索引从持久化样品来源和阶段输入输出维护或重建，只用于定位受影响内容；更正后标待复核，不自动重做科学分析或抹去实际操作。

### D6：最终结果授权驱动可核验整理与归档

宿主识别用户明确的最终结果意图，并保存该请求范围和来源，不以字符串包含“实验结果”直接触发。分析仍按需请求，不将最终结果自动等同于运行统计技能。

扩展整理任务的证据类型，文件结果保存实际文件哈希与记录引用；纯文字、数值或表格保存来源请求和回填记录片段哈希。修改现有“完成必须带文件”的限制，不通过制造空文件绕过。完成前核对当前请求清单均已回填、必要附件存在且可关联；关键缺项则继续收集。局部失效保留当前基线语义。

新增明确的 archive_request（授权 request_id、结果范围、触发原因、pending／done、阻塞信息），仅最终结果自动归档路径以本次整理完成为前提。保留原显式 finalize：用户主动保存当前材料时仍允许分析／整理待完成。两种路径均复用有效记录、当前库存核查与证据检查。

自动归档请求在失败后保留，后续工作流动作满足条件时继续，不要求另发归档指令；没有后台线程。日历连接或无日期待办可以随当前材料保留，不作为既有归档检查之外的新增阻塞。归档前回写 important，并在重要性修改影响文件哈希时刷新归档证据，不触发无关结果失效。

### D7：宿主执行日历操作，本地维护计划与远端收据

新增 `scripts/calendar_bridge.py` 及按需 `references/calendar-integration.md`。本地脚本提供 onboarding 状态、排期缺项、create/read/find/update 动作请求及收据校验；宿主会话根据用户选定服务执行插件／MCP 工具，再将真实返回写回映射。Python 安装脚本不假装能够安装任意宿主插件或直接操作登录。

首次安装及手动复制初始化返回 needs_calendar_setup，由会话询问服务和目标，优先复用已连接能力，否则引导安装连接及用户登录。核查选定服务的创建、读取、更新及查找能力，持久化服务绑定和能力结果，不保存认证凭据。适配契约在本轮实现，不要求一次内置所有厂商 SDK。

每个后续阶段（含涉及样品集合）有稳定 followup_id；正文列剩余步骤、样品、实验相对路径及匹配标识。首次创建前持久化待同步动作，成功后登记远端 id；响应丢失时先按稳定标识查询。服务无法核实不确定创建时，返回待核对，禁止盲目重复创建。

缺日期、开始时间或预计时长则会话集中询问，阶段事实先保存；使用项目时区（默认 Asia/Shanghai）解释计划时间。更新前读取远端：保持用户手改时间，只更新托管描述和剩余内容；识别完成时保留事项及完成标识。普通日历事件可用标题／正文表示完成，不假定有原生任务勾选字段。

日历是用户管理待办的位置，不另生成待办.md。内部映射、未排期信息及同步收据是可靠性元信息。用户改计划或删除事件不等于真实完成实验；缺失远端事项报告待核对，不能据此扣账或悄悄重建重复事件。

### D8：元数据与按需说明同步升级

`_record_metadata.py` 扩展 important 的管理及保留逻辑，已有手填合法值无明确变更时保留，缺失按 false 初始化；其他自定义属性、标签及正文保持原保护。completed/completed_at 的来源仍为整理任务，执行状态不新增到正文流程属性。

更新主入口和 references 的路由：阶段使用时读阶段模块，初始化／同步时读日历模块；实验确定时按 D9 启动实验级技能，结果分析和 PPT 仍按各自明确任务加载，不因启动技能自动执行全部功能。保留已有结果版本、精选与 PPT 内容约束，不把“实验重要”误作“所有结果精选”。

OpenSpec 配置说明将项目变更保存、历史归档与用户明确实验动作区分，实验“暂停”和最终结果是对应写入及归档授权。当前提案留在活动 changes 中；hisotry 的历史归档及 Git 提交不因规划完成自动执行。

### D9：实验确定时激活技能，保留按步骤执行边界

在宿主意图判定及 `project.py` 的目标解析契约中增加实验级激活：明确开始或继续某次实验，且类型与模板或方案已确定即定位目标，不以浓度等计算输入尚未提供为由推迟加载。顺序为用户明确指定、模板显式绑定、按实验类型配置匹配；明确指定的目标缺失或不适用时报告，不静默改用低优先级候选。多候选或未解决绑定冲突先展示选择。

沿用项目相对路径、名称索引和哈希校验，兼容现有 `skills/analysis` 及独立分析 skill，不新增全局技能库或要求批量迁移目录。模板绑定是明确的配置元信息，与 qPCR 模板中恰好同名的普通文本字段区分。缺失技能、工具不可用和计算输入不足分别报告，只暂停受影响工作。

激活只在会话加载目标入口和当前步骤相关内容，不写草稿、不分配编号、不创建库存计划。上样计算输入齐全后按 skill 自动执行；结果分析仍依明确请求或已确认方案中的明确任务，原始附件和最终结果整理不构成新增统计授权。

相比沿用结果阶段才 dispatch，这种方式使准备计算可在执行前使用；相比启动时运行全部分析，按步骤执行保持依赖和任务范围明确。模板负责结构，skill 负责公式与校验，主工作流不另维护通用的实验公式副本。

### D10：计算信息独立于实际操作和结果完成状态

在阶段输入和 workflow 状态增加独立计算集合，不将计算强塞进现有只接受 `user`、`confirmed_default` 的实际字段。每项计算有稳定身份、所属样品／阶段／步骤／尝试、输入值及单位与来源、采用参数、技能依据、结果与校验状态、依赖和替代关系；派生值使用明确计算来源。实测字段继续要求实际信息。

会话用只读或内存输入调用 skill 的计算能力，并根据 skill 实际支持的入口处理；不为任意既有分析技能虚构可执行计算接口。缺参只问当前步骤相关信息，异常返回原因而不截断为零；独立样品的有效计算不受无关失败阻塞。

预览同时展示拟用计算、已执行事实及实际库存清单，计算纳入预览哈希与确认范围。阶段确认或暂停保存可以写入尚未执行步骤的计算，正文设明确的计算部分，实际方法仍只列真实执行。新计算不更改步骤执行状态、库存事件、`completed/completed_at` 或最终结果意图。

实际量由用户报告或明确操作确认独立登记，可以不同于计算量；集中确认计算不视为操作确认。输入变化时未保存计算更新并标替代，已保存计算更正保留旧版和原因，依赖关系只标记受影响下游待复核。独立结果项和库存事件继续保留各自版本与更正语义。

### D11：固定可恢复的技能内容依据，续接不依赖当前安装版本

首次授权保存时固定本实验实际使用的技能标识、版本／哈希、来源相对路径及必要内容，并与计算参数和工具版本关联。复用内部内容快照思路，将实际依赖的入口、规则、脚本等保存在实验内部可校验快照中，不只记录一个指向会变动安装目录的版本号。仅激活或会话重算不提前落盘。

首次保存的依据须与会话实际计算及预览一致；若源内容在期间改变，先重新展示差异和受影响计算，不能在保存时悄悄固定另一套规则。续接校验并使用原依据，找不到必要内容或工具不兼容时说明受阻，不从新版本补造旧结果。

显式升级采用差异与影响预览、确认及新快照，保留旧引用和计算历史，只重算相关部分。实现增量状态时明确支持的版本与迁移路径；旧状态缺少技能依据时标为未知，不能反向把当前安装内容登记为当年使用内容。旧加载器不得把新增状态当作旧版自动降级。

### D12：统一记录历史保存路径，重试复用首次确定的历史身份

在真正的实验项目根使用固定角色的 `history/`，文件名为 `<实验编号>_<YYYYMMDD-HHMMSS-ffffff>.md`；时间为本次确认修改的北京时间，不取旧文件系统 mtime，也不在恢复时重新生成时间。与 OpenSpec 的 `hisotry/` 分开，源码仓库不因规划更新产生虚拟实验目录。

抽取统一的记录替换协调，覆盖阶段保存、旧 CLI 的记录替换及受管属性同步。仅在已有记录字节内容将实际变化且保存已获授权时先保存完整旧版，再替换当前记录。相同内容、首次保存、纯会话计算不产生历史；既有旧 CLI 的轮次副作用不能成为制造无内容变化历史的理由。历史元信息关联原实验、稳定动作、修改依据、旧记录哈希与目标路径。

历史路径、时间及目标内容在首次准备保存事务时确定，并加入原有动作写入清单；恢复复用，先确认旧版留存才推进当前记录。不同修改若产生同一目标名则在首次事务准备中重新分配时间身份，绝不覆盖另一历史；相同动作重放不重复增加历史或记录轮次。旧 CLI 及属性更新路径也需复用协调和相关锁，不能只修阶段 save。

history 位于项目根，旧记录中的相对附件链接不能直接原样搬过去。保存完整旧记录内容时按原实验位置解析受管本地引用，再转换为相对历史文件的有效引用，保留原内容哈希和映射依据；外部 URL 及其他人工内容保持原意。附件本体不复制，路径搬迁仍以项目相对关系追溯。无法可靠处理的引用列明原因，不假称链接有效。

现有 `.experiment-workflow/record-history`、归档历史、模板快照、结果版本和库存账目不删除、不合并为这一目录；旧哈希历史没有可靠业务时间时不批量伪造命名。采用完整记录而非仅差值，使更正前的计算上下文、实际量与属性可独立查看，代价是更多文本副本。

### D13：项目级历史显式纳入单实验归档，qPCR 迁移保持暂缓

现有归档扫描只遍历实验目录，需用历史关联清单将根 history 中本实验的文件及哈希显式加入归档证据；路径按项目根定位，不依赖其在实验目录下。归属由已保存关联确认，不只按文件名前缀推测；其他实验历史与 OpenSpec 的 hisotry 不纳入。检查缺失、外部修改及历史附件引用，新历史使相关归档待刷新，不使无关分析失效。

归档清单及恢复内部写入本身不再制造记录历史；只有确实改变实验记录正文或受管属性才走 D12，避免归档扫描与历史追加递归。保留显式归档、最终结果自动归档的原授权与库存门槛，保存计算不自动触发实验结束或结果完成。

现有 `assets/qPCR.md` 及已冻结模板原文保持不变，本次不迁出公式或计算块、不创建具体 qPCR 专业技能。缺失该技能时依 D9 阻塞相关自动计算，旧模板公式不是后备执行器。通用契约使用临时测试技能和合成输入验证，不把测试能力宣称为 qPCR 已接入。

## Risks / Trade-offs

- [旧入口将所有计算都路由到结果阶段] → 同步主入口与所有相关参考，分别验证实验激活、上样计算、独立结果分析，禁止只改一个入口留下相反规则。
- [计算被当作实测、执行或库存扣减] → 独立计算模型与预览，实际字段及事件只接受实际依据，保存计算不改变结果完成标记。
- [只固定 SKILL 名称或当前哈希无法恢复旧规则] → 保存实际使用的必要内容及来源，续接校验，明确升级后切换；缺失依据不伪造。
- [history 移到项目根后断链或漏归档] → 调整历史中的受管相对链接，记录原哈希与映射，并显式按实验关联纳入归档证据。
- [时间命名在恢复时变化或不同写入路径漏备份] → 首次动作内固定历史身份，统一正文与属性替换协调，以中断及重放验证。
- [误把通用规则变更扩成 qPCR 重建] → 明列暂缓范围，验收核对现有模板内容未改，缺失具体 skill 如实报告。
- [旧说明称模板默认值视为实际执行] → 明确列为行为修订，普通与阶段模板统一确认；实现、入口和术语同步更新。
- [旧 read_state 将所有非 v3 状态当旧版迁移] → 改为显式识别支持版本，未知未来版本拒绝降级，迁移保留备份并校验。
- [阶段完成与未执行步骤混淆] → 分开暂停片段和真实步骤状态，验证第三步未做时不被完成，日历同样保留剩余事项。
- [保存、库存和日历部分成功] → 使用动作收据、稳定事件和远端查找，重试只推进未完成环节，不宣称跨系统原子性。
- [服务插件能力因宿主不同而不足] → 首次配置核查并明确 needs_setup／blocked，保留独立记录，不硬编码 Outlook 或伪装同步成功。
- [只按文件存在判断结果整理] → 增加输入范围、实际回填片段和附件关联清单，覆盖文字结果与缺项场景。
- [更正传播过宽或过窄] → 保存关系证据，提供具体复核清单，无范围依据时只要求定位，不把所有任务重置。
- [已有测试日志来自其他环境] → 保留为历史证据；实施验证报告记录本次环境、运行命令及实际结果，不据历史日志宣称 Windows／远端服务通过。

## Migration Plan

1. 保留 B01—B15 及旧 CLI，增加纯校验和读取路径；先建立结构化模板、状态及日历动作契约的测试。
2. 为 v2／v3 状态进行显式、可重复的备份迁移；已有记录保持正文及身份，阶段信息不明时留在普通模式。新字段只对已知数据初始化，不反推历史阶段、实验结束或样品来源。
3. 新实验显式固定模板快照；已有实验没有旧内容证据时不声称已冻结历史，切换阶段模式需展示映射与确认。
4. 扩展样品及库存调整／产物计划，复用原快照和事务恢复。新增信息不覆盖既有 parent/sources 语义；已有余额不批量重算。
5. 接入阶段保存、文字结果证据和最终归档授权，再接入首次安装日历引导及宿主动作收据。
6. 更新模板、按需参考、安装说明、配置及项目设计索引，在合成项目上跑新增场景和全部已有回归。宿主实际日历在用户首次配置和真实排期中校验，不为提案创建测试日程。
7. 回退时保留 v4 状态和远端事项映射；仅在没有后续事务且明确恢复依据时从备份回退，旧加载器不得直接打开 v4 当 v2 迁移。已经发生的库存消耗和远端事项不能通过还原旧文件假装撤销。
