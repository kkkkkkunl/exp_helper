# 普通记录与补录

本模块不要求分析意图判定，不读结果模块或全量技能库。

用户已明确开始或继续且实验类型与方案确定时，另按 [实验技能模块](experiment-skill-module.md) 立即定位目标；这不意味着执行新的结果统计。上样计算由该 skill 负责，普通数值和计算仍先留在会话。

## 交互与保存

1. 在会话收集原话与实际信息，集中整理，只问缺项或冲突。普通数值回答不自动写项目文件。
2. 使用 project.py validate --scope record，仅校验相关配置。若用户使用阶段、暂停、继承或提交最终结果，转 [阶段交互模块](stage-record-module.md)。
3. 普通记录也可用阶段交互脚本的 preview/save，提供 method_text 和实际日期；没有阶段模板时维持普通模式，不自动猜测阶段。
4. 阶段确认、暂停或明确最终结果构成对应写入授权。既有显式 CLI 仍可在用户要求保存时使用：
~~~text
py -3.9 -B scripts/workflow.py --project <项目根> start --request-id <输入唯一ID> --input <原话.txt> [--experiment <已有编号>]
py -3.9 -B scripts/workflow.py --project <项目根> record --experiment <编号> --file <候选记录.md>
~~~
5. 重试复用 request-id，新输入使用新 ID。跨会话先 list/status；不能仅凭新会话没有编号重复建实验。
6. 新正式记录由 `assets/experiment-record.template.md` 唯一生成结构：元信息、基本信息表、目的、实验方案（参考方案／实验方法）、结果、附件；`## 上样计算` 只在实验方案和结果之间。正文可空，不放模板占位符、说明文字或 TODO；保存前校验标题层级和顺序。旧格式普通编辑保留排版及原语义校验。
7. 旧记录只有明确迁移时先运行 `workflow.py ... migrate-preview --experiment <编号>`，展示原文归属、候选正文与 `preview_hash`；确认后运行 `migrate --experiment <编号> --preview-hash <哈希>`。原版进入项目根 history，同一预览重试不重复生成历史。未知归属先核对，不丢弃原文。
8. 阻断性缺项与冲突优先用宿主问答框；可靠候选供选，其余开放输入。问答框不可用时集中编号追问，继续接受自由文本，已知值不重问。单项实际值正文只写确认值及必要单位，原话、确认与时间读取依据在状态及原始输入中保留。相对时间先核对北京时间候选，再以 `HH:mm` 记载。
   正文内容选择遵循 [记录规则 R-07、R-10](record-rules.md)：未提供信息及“未记录”等缺项说明默认省略；用户明确报告的未执行操作也默认省略，仅在属于有依据的关键方法差异或用户明确要求时保留。必要缺项仅在交互中集中核对，不凭惯例补值；正文省略不改变原话、追溯依据和真实步骤状态。
9. 附件按 archive.py move 的复制校验／冲突规则处理，链接指向归档后文件。命令管理 completed/completed_at/important，保留其他属性。人工修改时先展示合并并确认，再按当前哈希授权写入。
10. 保存后立即加载库存模块，核查本轮真实操作；无变化登记 none 和依据，不询问是否手动管理库存。同事件不因新轮次重复扣账。
11. 普通过程保存不等于实验结束。明确最终结果按交互模块自动整理／归档；单独请求保存当前材料仍可独立 finalize。

10. 经确认的上样计算写入独立计算部分，保留输入、单位、技能依据及结果；未操作时不写为实际执行。记录正文和受管属性实际变更前保存完整旧版到项目根 history，重试及内容不变不重复生成，原内部历史保留。

## 局部更新

只补日期或操作说明且不影响结果时保留整理完成标记；涉及结果、分析输入或参数的变化必须明确受影响任务。旧 CLI 的 start 支持 affects-results/affects-analysis，record 支持 affects-results。

结果章节多任务变更但范围不明时不能全量猜测重置，先明确范围。外部修改范围未知时保留任务历史并将总体整理状态置为待定位；实际已执行操作不撤销。

状态查询或工作流调用时核查外部证据，没有后台监听。直接显式调用写入命令属于保存动作，不应在普通数值回答后调用。
