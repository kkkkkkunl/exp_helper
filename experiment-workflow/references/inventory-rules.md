# 样本台账规则

台账是库存的**唯一数据来源**：每个库存单位一个 markdown 文件，frontmatter 承载结构化字段，Obsidian 直接可读。不要另建一份 Excel 或数据库，避免两套库存。

## 库存单位与字段

**R-17** 库存单位是"可独立取用和管理的实体"（一管、一瓶、一块组织），关联其来源样本。

**R-18** 样本表字段：编号、处理、存放地点、剩余量、单位。液体样本另加浓度。

**R-19** 处理指**实际实验处理**（药物、浓度、时长），不是入库或出库操作。

**R-20** 每个库存单位采用**固定计量单位**，同类单位允许换算。

## 编号

**R-21** 基础编号 = 实际形成日期 + 全局当日递增字母：`20261031-A`，同日在全局库依次 A–Z、AA、AB…。历史补录用实际形成日期；日期不明时询问；已有编号一律保留。

**R-22** 分装沿用来源编号并追加数字：`20261031-A-1`。再次分装追加层级：`20261031-A-1-1`。同一来源下数字递增且**不回收复用**。

**R-23** 多来源混合产生**新的基础编号**，关联全部来源，分别扣减来源的实际用量，新样本独立管理余额、浓度与位置。

**R-24** 编号由 `allocate_id.py` 分配，带文件锁，并发会话不会撞号。不要手工造号或重排。

## 单位与换算

**R-25** 同类单位可换算（mg↔g、uL↔mL），但必须在 `experiment-project.yaml` 的 `units.convert` 里显式声明。

**R-26** **没有密度依据，不得在质量与体积之间换算**。脚本会拒绝并提示询问用户密度。

**R-27** 数量未知、矛盾或不足时询问；暂停相关变更，继续其他整理。

## 起始量

**R-28** 旧样本起始量未知时**必须询问，不能从取用量反推**。

**R-29** 唯一例外：模板明确描述了新样本的制备量时，可据此生成待确认的入库量。

**R-30** 初始数量未知时不填 0，保留为未知并在对话中提问。

## 变更

**R-31** 变更类型：新增、取用扣减、归还、分装、转移、耗尽、废弃。每种都关联对应实验，只依据**实际执行**的信息。

**R-32** 净消耗 = 实际取用数量 − 归还数量。损耗仅在用户明确提供时扣除。

**R-33** 扣减必须确定到**具体库存编号**。不得凭名称相似推测取用对象；无法确定时询问。

**R-34** 两段式提交：

```
inventory.py plan   → 生成 库存变更清单.md，展示给用户
inventory.py commit --plan-hash <指纹> --confirmed-by <确认依据> → 确认后才写台账
```

**没有授权不得 commit。** 用户直接给出信息完整的具体库存指令，可作为该项授权，不重复确认；从实验描述推导出的变更须展示清单并确认。等待确认期间继续独立的记录工作。

**R-35** 幂等：每个真实变更项有独立 event_id；重试沿用该 ID，重复运行只跳过、不重复扣减。不要靠"看一眼清单里有没有"来判断。

**R-36** 分装从原管余额扣除，子管各记实际数量，不重复计算来源库存。全部分装后原管余额为零，退出在库列表并保留来源关系。

## 浓度

**R-37** 液体记录浓度值、单位，必要时注明测量对象（如"葡萄糖 10 mM"）。允许多个组分浓度并存。

**R-38** 普通取用及不改变组成的分装**沿用原浓度**；稀释、浓缩或混合必须**单独核实**新浓度。

**R-39** 浓度缺失时询问，由用户决定：补充、未测定、或不适用。不自动推算、不填零。

**R-40** 输入充分且计算条件成立时，可生成**明确标记为计算值**的新浓度，与变更清单一起确认。计算值不得冒充实测值。

## 视图

**R-41** 默认在库列表简洁展示编号、处理、存放地点、剩余量、单位、浓度。出入库历史另存，通过样本文件查看。

**R-42** 耗尽或废弃的条目退出在库列表，但保留历史供 Obsidian 查阅。

**R-43** 未登记的试剂不建账。试剂、标准品、储备液只有在明确登记为库存对象后才管理；未登记时只在方法里保留用量。

**R-44** 实验方法与样本双向关联：方法里的样本编号链接到样本文件，样本文件的 `experiments` 字段列出相关实验。脚本维护样品中的实验编号；模型须把样品文件链接写回记录并检查可解析，不要另增样本分区。
