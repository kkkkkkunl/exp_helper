# 分析调用与结果版本

## 调用

**R-45** 按 `experiment-project.yaml` 的 `analysis_map` 把实验类型或数据类型映射到分析 skill：

```
python scripts/project.py dispatch --experiment-type 流式 --data-type fcs
```

**R-46** 在项目 skills/analysis/index.json 中按名称定位实际 SKILL.md；available 表示文件可读且索引哈希一致。命中后**加载该 skill 并遵循它规定的工具与分析要求**。本 skill 不重复定义统计方法。

**R-47** 无匹配、工具不可用、或必要分析信息不足时：在对话中提出，继续完成不依赖分析的整理，**不虚构结果**。

**R-48** 命中多个候选时询问用户，不自行挑选。

## 结果项

**R-49** 结果项是可独立选择和追溯的单元：一张分析图、一份统计表，或共同表达同一结果的一组文件。编号 `R-<实验编号>-NN`，分配后固定。

**R-50** 每个结果项可回溯到实验、数据与分析参数。

## 版本

**R-51** 数据或分析参数变化产生新版本；参数指纹相同且文件相同则视为重复，不建新版本。

**R-52** 保留旧版本及其标记。新版本默认**未标记**，由用户重新选择。

**R-53** 仅调整排版而不改变结果内容时，可保留标记。

## 标记

**R-54** 标记由用户决定，默认未标记。不要替用户标记，也不要在用户未表态时推测。

**R-55** 标记仅表示用户选中，用于检索与汇报选材，**不代表统计显著或质量审核通过**，不改变数据与分析结论。

**R-56** 支持跨实验、跨项目筛选已标记结果：

```
python scripts/results.py filter --kb <知识库根> --marked
```

## 存储

结果项目录：

```
results/<结果项编号>/
├── index.yaml      # 版本、参数指纹、文件哈希、标记
├── v1/
└── v2/
```

字段定义见 `schemas.md`。跨项目筛选依赖知识库根目录的 `_results-index.yaml` 登记表，由脚本自动维护。

## v2 运行证据

使用 workflow.py analysis 登记任务状态、skill 版本、输入/输出哈希与参数，实际执行由已加载的分析 skill 完成。命令及归档要求见 `result-module.md`。
