# experiment-workflow v3 修改说明

本版落实已确认的渐进加载、项目内技能库及独立状态设计。保留 v2/v2.1 原文件；本次没有在真实实验项目中安装或改动真实库存。

## 1. 渐进式披露

SKILL.md 从 144 行缩减到 31 行，字符数从 5327 降至 1364，入口字符减少约 74.4%。这不是实际 token 消耗的测量；真实用量取决于本次会话加载的模块。

按需页面：

| 文件 | 加载时机 |
|---|---|
| references/record-module.md | 记录或补录实验 |
| references/result-module.md | 明确要求结果整理、分析、计算或绘图 |
| references/inventory-module.md | 每次记录完成后，或独立库存指令 |
| references/archive-module.md | 保存当前记录归档 |
| references/setup.md | 安装、首次初始化、技能库维护 |
| references/report-rules.md | 用户要求汇报 PPT |

只记录不读取结果模块或所有分析 skill，不再执行全量依赖校验。project.validate 默认只校验 record；inventory、analysis（需名称）、report 和 all 为独立校验范围。

## 2. 项目内安装和名称索引

新增 scripts/install.py、scripts/skill_store.py。

```text
项目根/
├── experiment-project.yaml
├── samples/
└── skills/
    ├── experiment-workflow/
    └── analysis/
        ├── index.json
        └── <名称>/SKILL.md
```

安装示例（解压后）：

```bash
python experiment-workflow/scripts/install.py --project <你的项目根>
```

安装自动建配置和缺失目录。已有配置保留；已有主 skill 不覆盖。手动复制主 skill 后首次使用执行同一命令加 --init-only，仅补齐缺失内容。

分析技能安装与解析：

```bash
python <主skill>/scripts/skill_store.py --project <项目根> install --source <分析skill目录>
python <主skill>/scripts/skill_store.py --project <项目根> resolve --name <名称>
```

配置与索引都用项目相对路径，搬迁项目后仍可解析。按名称只读取索引条目和目标文件，不遍历全部正文；安装/更新维护阶段才读取 frontmatter 并刷新索引。目标修改后哈希不一致时提示刷新。名称不存在不自动下载，同名不自动覆盖。安装目标位于源内部时提前拒绝，防止递归复制。

## 3. 库存自动衔接

每次 record 完成增加记录轮次，并返回 next_action: inventory_review。主 skill 指示模型立即加载库存模块并完成本轮核查，无需用户另发库存请求。这是 skill 执行流程，不是后台监听服务。

- 没有变化：记录核查依据并结束，不询问是否要手动管理仓库。
- 有推导出的变更：生成具体清单，确认后提交。
- 有信息完整的明确直接指令（包括报废）：该指令作为该项授权，生成计划并直接提交，留存授权依据，不重复确认。
- 同一真实操作保持 event_id，不因新一轮记录重复扣账。

库存事件幂等、整批快照校验、共享锁、故障恢复与分装/混合检查继续保留。

## 4. 整理完成与归档分开

新增 workflow.py organize 命令，内部 result_tasks 记录本次要求整理的已有结果；analysis 记录分析进度；archived/archived_at 记录归档。

文档自动管理的流程属性仅为：

```yaml
---
completed: false
completed_at: null
---
```

已有标签和其他自定义属性保留，不再自动加 status 或默认 tags。全部已请求的结果整理任务完成才变 true/实际完成时间；纯过程记录保持 false/null。分析是否完成和归档与否都不直接改变这两个值。

finalize 不要求分析或结果整理完成；会保存现有材料，并在内部清单保留待分析/待整理/待处理事项。仍要求本轮记录已写入、原始输入及记录可追溯，以及本轮库存核查/需要的提交完成。

## 5. 局部更新与保护

- 无关的日期、操作说明补录保留整理完成标记和完成时间。
- start 可通过 affects-results/affects-analysis 指定受影响任务；分析任务通过 analysis_tasks 关联整理任务。
- 修改结果文件，只使拥有该文件证据的整理任务失效。
- 修改分析数据/参数/输出，只使关联整理任务失效。
- 多任务的结果章节发生变化且不能确定范围时，要求指定受影响任务，不全量重置。外部修改范围待定位时，暂时清空总体完成标记，各任务历史保留。
- 自动属性同步更新记录哈希，但不把其他人工修改当成自动生成基线；原有人工修改保护继续有效。

新写入的项目内证据路径也使用相对路径。外部文件变化在下一次状态查询或工作流调用时检测，没有实时文件监听。
