## 用户可见行为

| 场景 | 行为 | 对应实现 |
|---|---|---|
| 普通数值回答 | 保持会话草稿，无项目写入；集中追问缺项 | 阶段 preview、宿主交互协议 |
| 确认阶段 | 对已展示记录及库存清单按范围保存；预览变化须重确认 | stage_workflow.py 的预览哈希和动作收据 |
| 暂停 | 已做部分完成收尾，未做步骤仍未执行，剩余内容进入日历 | segments、逐样品 steps 与 followups |
| 样品继承 | 新实验使用旧产物，关联来源，不重做前序记录 | produced_by、独立编号及来源关系 |
| 失败重做／事实更正 | 分别保留尝试与更正依据，相关下游待复核 | attempts、corrections、库存 adjust 与 review-notices |
| 最终结果 | 明确最终意图才整理；文字无需伪造附件；整理完成后结束并自动检查归档 | 结果来源／回填核验、execution 与 archive_request |
| 归档受阻 | 保留已完成状态和授权，补齐后在后续调用继续 | 原有记录／库存／证据检查 |
| 重要标记 | important 默认 false、可更改，与结果精选独立 | 属性保留及显式 important 命令 |
| 日历接入与续接 | 首次选择服务，宿主连接插件／MCP；补问排期、更新原事项、保留手改时间 | calendar_bridge.py 与日历宿主收据协议 |

## 文件与兼容

- 新增 stage_templates.py、stage_workflow.py、calendar_bridge.py、lineage.py，职责分别为模板固定与升级、阶段动作、日历协调及可重建来源复核。
- workflow 状态为 v4，显式迁移 v2/v3 并备份；未知未来版本拒绝降级。普通旧模板保留，但预设参数同样先展示确认。
- 新增通用作者模板和不含真实实验参数的流程结构示例，均位于 assets；作者规范和使用说明位于 references。
- 已有库存快照、分组、事务恢复、人工修改保护、结果版本及按需分析继续保留。库存更正以新事件追加，阶段产物不等同于分装，不推断浓度或跨材料数量关系。
- 记录管理 completed/completed_at/important；其余执行和同步信息保留在内部。日期补录、重要性及日历收据不使无关结果整理失效。
- 首次安装只报告需要日历配置的实际状态，由宿主选择、安装或连接工具并完成用户登录；不是本地 Python 直接安装任意宿主插件。

## 本次有效验证

环境：Windows，Python 3.9.10，UTF-8，项目内隔离临时目录。默认 python 指向旧版外部科学软件，因此使用 py -3.9；默认临时目录的文件替换受限，测试改用项目内临时目录，不削弱原子替换实现。

| 验证组 | 结果 | 证据 |
|---|---|---|
| unittest 合集 | 51 项通过：19 项 v4、17 项 v3、15 项既有回归 | _test_v4.py、_test_v3.py、_test_regressions.py 的最后一轮运行 |
| YAML 子集 | 24 个检查点通过，0 failures | _test_yamlish.py |
| 既有端到端 | 39 个检查点全部通过 | _test_e2e.py |
| 交付模板 | 通用模板 1 阶段、流程示例 4 阶段，均通过结构校验 | stage_templates.validate 与交付 assets |

命令在 experiment-workflow/scripts 中执行：

~~~powershell
$env:TEMP='F:/experiment-workflow/_v4_test_tmp'
$env:TMP='F:/experiment-workflow/_v4_test_tmp'
$env:PYTHONUTF8='1'
py -3.9 -B -m unittest _test_v4 _test_v3 _test_regressions -v
py -3.9 -B _test_yamlish.py
py -3.9 -B _test_e2e.py
~~~

原始输出及最终回归摘要见 [v4-验证日志.txt](v4-验证日志.txt)。v3 测试仅按已确认行为更新两类夹具：结果完成前实际回填链接，文档属性集合包含 important；未删除原有保护断言。

新增验收覆盖三步只做两步暂停、A/B 不同进度、转化产物继承、真实重做、前后更正、未知版本、模板内容固定与升级、记录写入后恢复、预览后库存变化须重新授权、纯文字结果、归档等待恢复、安装后标准输入预览零写入、日历不确定响应及保留手改时间。

## 验证范围

日历验证采用两个模拟服务和模拟宿主工具收据，验证的是接入契约、状态推进和可靠同步。真实服务由首次安装时选择并授权连接，本轮未向真实日历创建测试事项，也未验证某个真实账户的读写权限。

本轮数据均为合成数据，验证本地文件、CLI、锁及恢复行为；不等同于真实科研分析、具体 qPCR 规程或网络共享文件系统的验证。PPT 保留宿主生成规范和内容约束，没有新建独立渲染引擎。
