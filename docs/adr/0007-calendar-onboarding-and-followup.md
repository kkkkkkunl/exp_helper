# 首次安装日历引导与后续实验排期

状态：已实施；各轮修订边界保留如下，当前验证范围见 [v4 实施报告](../v4-实施说明与验证.md)。

## 决定

1. 首次安装时询问用户选择日历服务和目标日历，安装或连接对应插件／MCP；不固定某个服务。手动复制时在首次初始化执行相同引导。
2. 暂停先保存阶段记录。后续实验缺少排期时集中询问日期、开始时间及预计时长，已有信息不重复询问；齐全后直接写入日历。
3. 每个后续阶段建立一条日历事项，描述包含待做步骤、样品编号及实验记录位置，不按每个步骤重复建事项。
4. 同一待办再次暂停时更新原事项，继续实验后更新剩余内容，实际完成后保留事项并增加已完成标识。用户手工调整的排期予以保留。

## 实现边界

- 由支持插件或 MCP 的宿主会话执行服务选择及安装连接引导；本地初始化脚本提供配置状态与后续动作，不能将未连接状态报告为成功。
- 项目只保存目标服务、日历标识和事项映射等配置，不复制宿主的认证凭据。
- 日期或连接能力不足时保留待同步状态并说明缺项，独立的实验进度仍可保存。不把尚未成功创建的事项报告为已排期。
- 日历是用户查看待办的位置；内部进度及事项标识仅用于恢复和防重复，不另建用户维护的待办.md。

## 确认依据

用户在[设计访谈第四轮](../阶段式实验与交互记录设计访谈.md)回复“17 在第一次安装时，询问用户，安装对应的插件或MCP 18 同意 19 同意”。
