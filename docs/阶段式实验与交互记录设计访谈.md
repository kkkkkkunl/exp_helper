# 阶段式实验与交互记录：设计访谈

状态：访谈已收束，方案已进入 OpenSpec apply 并实施；验证范围见 [v4 实施报告](v4-实施说明与验证.md)。

## 用户已明确的需求

1. 为后续实验记录模板增加阶段设计规范，允许选择暂停位置及从中间阶段开始。
2. 用户举例的流程为细胞培养、RNA 提取、逆转录、qPCR；样品准备阶段可以暂停。本例仅用于说明流程组织需求，不构成实验操作规程。
3. 新实验可以使用此前实验获得的样品，不要求重做此前的样品准备阶段。
4. 会话根据实验内容提示下一步，由用户主动提供样品量等实际数值，再整理为实验记录。

## 现有文档中的约束

- [记录规则](../experiment-workflow/references/record-rules.md)：一次实验执行对应一份记录；补录沿用原实验编号；模板内容与版本在创建实验时固定。
- [记录模块](../experiment-workflow/references/record-module.md)：记录后进入库存核查；跨会话先查询已有状态；实际内容不得虚构。
- [现有记录模板](../experiment-workflow/assets/experiment-record.template.md)：包含目的、参考方案、实际方法、结果和附件，尚未定义阶段入口、暂停位置及跨实验样品来源字段。
- [OpenSpec 配置](../openspec/config.yaml)：草稿不自动保存，仅按用户明确请求写入文件；Git 提交由用户主动执行。

## 设计树

### 第一轮：已确认

用户已明确回复“Q1 同意 Q2 a Q3 同意 Q4 同意”。

1. 同一实验暂停后继续沿用原实验编号；使用旧样品开展新的实验则创建新实验编号，关联样品、来源实验和来源阶段。前序操作通过链接追溯，不作为本次实际操作重复书写。
2. 下一步操作和待填信息依据已选模板或用户提供的实验方案。缺少方案或关键参数时指出缺项，不自行拟定完整流程，也不把推测写成实际执行。
3. 按步骤集中收集相关实际信息，接受自由文本及一次提供多步骤内容，只追问缺失或冲突信息。阶段结束展示汇总，供继续、暂停或更正。
4. 普通回答只整理为会话草稿；用户明确说“确认本阶段”或“暂停并保存”后才将记录和恢复状态写入项目文件。跨会话恢复依赖已保存状态。Git 始终由用户主动提交。

对应已接受决定见 [ADR 0003](adr/0003-stage-continuation-and-interactive-recording.md)。以上确认不代表尚未讨论的整体设计已获实施授权。

### 第二轮：已确认

用户对 Q5—Q10 明确回复“全部同意”。

5. 模板采用阶段包含步骤的层次，声明正常入口、暂停点及继续条件。会话可随时停止；实际操作在未预设位置中断时保存真实进度，不自动认定可直接继续。
6. 模板声明产生新材料时为产物建立新样品编号，关联来源样品、产生实验及阶段。普通取用沿用原样品身份，分装继续采用既有规则。继承定位到具体样品。
7. 同次实验允许各样品具有不同阶段进度；相同步骤可集中展示和填写，部分样品继续不使其他样品自动变为已执行。
8. 模板预设值先作为参考展示，用户可更正或明确确认“本阶段按所列参数执行”，集中确认操作条件及用量。实测结果只能来自用户提供的信息。
9. 缺少必填信息时可暂停并保存已确认事实和待补进度，但不标为阶段完成。未知值不填零；待补事项仅保存在交互状态。未测定或不适用由用户明确选择且符合字段规则。
10. 阶段汇总同时展示记录及具体库存变更清单；用户确认覆盖已展示的内容。未展示或信息不完整的库存操作不提交，不阻塞独立的实验进度保存。

对应已接受决定见 [ADR 0004](adr/0004-stage-model-sample-lineage-and-confirmation.md)。

### 第三轮：已确认

用户明确回复“Q11—Q15 同意”。

11. 同一实验内真实重做阶段时新增尝试，保留之前实际操作、结果及消耗；只重做失败样品。完整重复开展新的实验另建编号。
12. 允许接入缺少完整历史的旧样品或外部样品，保留未知来源，不补造历史。缺少具体身份、取用量或单位时暂停相关库存提交；缺少模板继续条件时不自动提示直接继续，但可保存进度。
13. 模板允许的分支由用户选择；超出模板的调整先展示并确认。实际偏离照实记录，会话不自行判断未经方案支持的操作是否可行。
14. 更正已保存事实时保留更正前后及依据，展示影响范围后确认保存；相关样品、阶段或结果待复核，真实已发生的操作保留。库存更正另列调整清单，避免重复扣减。
15. 旧模板支持普通记录，不自动推断阶段结构，预设参数仍先确认。新模板采用阶段规范；实验开始时固定模板版本及内容，暂停后沿用。升级前展示映射及影响并确认。

对应决定见 [ADR 0006](adr/0006-retries-corrections-and-template-compatibility.md)。

### Q16：用户的新要求

用户原话：“输入暂停，视为阶段完成，后续实验内容进入代办事项。输入实验结果，自动整理后，视为实验结束，结果整理完成后，自动归档。同时，在归档时候，可以标记，是否重要”。

- 输入“暂停”：当前阶段视为完成，后续实验内容转入待办事项。
- 输入“实验结果”：启动自动整理，整理后视为实验结束；结果整理完成后自动归档，无需再单独发出实验记录归档指令。
- 实验记录归档时支持用户选择是否重要。
- 这些是对实验文件流程的明确要求，不授权自动 Git 提交，也不改变 OpenSpec 项目变更历史的提交标准。
- 本条替代此前“暂停保存不标为阶段完成”和“实验记录必须另发归档指令”的相关建议；尚未确定的细节不据此擅自补全。

已明确的要求见 [ADR 0005](adr/0005-pause-result-and-automatic-archive.md)。

### Q16 补充边界：已确认

用户回复“a同意b同意c同意d 待办直接写入日历即可。e同意”。

- A：中途暂停时，已执行部分作为本次已完成阶段；未执行步骤和后续内容进入待办。步骤保留真实状态，缺数据另列待补，不把未做步骤标成已执行。
- B：明确提交本次最终结果的表达才触发结果整理和结束流程。普通讨论、初步结果、单独上传附件不自动结束。所提交的结果写入记录且附件关联完整后，才能标为整理完成；缺少必要内容先补齐。
- C：库存、记录有效性或证据检查未通过时，保留已经达到的结束及整理状态，归档待处理；补齐后延续本次授权自动归档。未完成待办保留，不自动勾选。
- D：待办直接写入日历，不采用每次实验单独建立待办.md的建议；具体接入及排期规则见第四轮。
- E：整次实验采用 `important` 属性，用户可指定重要或普通；未指定默认普通，不阻塞自动归档，之后可以修改。此标记独立于结果精选。

### 第四轮：已确认

用户回复“17 在第一次安装时，询问用户，安装对应的插件或MCP 18 同意 19 同意”。

17. 首次安装时询问用户选择日历服务及目标，安装或连接对应插件／MCP；不固定为当前会话的 Outlook。手动复制安装时在首次初始化完成同一引导。
18. 暂停先保存阶段记录；缺少后续排期时集中询问日期、开始时间和预计时长。已有信息不重复询问，信息齐全后直接写入日历。
19. 每个后续阶段一条日历事项，描述包含待做步骤、样品及实验记录位置。再次暂停更新同一事项，继续后更新剩余内容，完成后保留事项并增加已完成标识。用户手动调整的排期予以保留。

对应决定见 [ADR 0007](adr/0007-calendar-onboarding-and-followup.md)。

## 日历能力核查

- 项目现有文件中未发现日历接口或配置；日历待办是新增集成能力。
- 核查时当前会话的 Outlook Calendar 连接器列出一个可写的默认“日历”；用户选择在首次安装时确定目标，该核查结果不构成默认绑定。
- 日历事项创建接口要求开始和结束时间，因此不能把未给日期的待办擅自排入某一天。
- 本轮仅核查能力，没有创建实际日历事项。
