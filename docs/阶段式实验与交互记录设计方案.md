# 阶段式实验模板与交互记录设计方案

状态：已按 OpenSpec apply 实施；当前实现与验证范围见 [v4 实施报告](v4-实施说明与验证.md)。

## 依据与范围

本方案合并[设计访谈](阶段式实验与交互记录设计访谈.md)及 [ADR 0003—0007](adr/)，采用用户最后确认的修订。访谈早期关于暂停不算阶段完成、必须单独请求实验归档的建议已被替代。

本次目标是通用模板规范、阶段与样品来源模型、交互记录、日历待办及自动结果归档。用户给出的细胞培养、RNA 提取、逆转录、qPCR 仅作为流程结构示例。仓库尚无实际 qPCR 操作规程；不由本方案补造实验参数、测量结果或可安全暂停的条件。

## 用户操作与响应

| 输入或动作 | 系统响应 | 文件与状态影响 |
|---|---|---|
| 提供实际步骤、数量等信息 | 按当前模板步骤集中整理，只追问缺项或冲突 | 形成会话草稿，尚不写入项目文件 |
| 确认本阶段 | 依据此前已展示的记录汇总及具体库存清单，按确认范围保存 | 更新记录及进度；仅提交已展示且信息完整的库存项 |
| 暂停 | 已执行部分作为本次已完成阶段，剩余内容转日历待办 | 保存事实、真实步骤状态及恢复位置；缺数据另列待补 |
| 继续已有实验 | 读取已保存进度及日历事项，核对当前样品后继续 | 沿用原实验编号，更新原待办而非重复创建 |
| 用旧样品开展新实验 | 选择具体样品及允许的阶段入口 | 新建实验编号，关联来源，不复制前序操作为本次事实 |
| 明确提交最终实验结果 | 整理本次提交结果，关联记录及附件，整理后视为实验结束 | 整理完成后自动归档；未满足归档检查时等待补齐 |
| 指定重要或普通 | 设置整次实验的重要标记 | `important` 为 true 或 false，默认 false，可事后修改 |

普通讨论、初步结果、单独上传附件以及引用关键词的描述不构成结束指令。最终结果指令只授权本次结果整理、相应保存及后续实验记录归档，不授权生成未请求的数据分析或 Git 提交。

## 模板设计规范

### 阶段与步骤

- 方法模板以阶段包含步骤，声明正常入口、允许暂停的位置及继续条件；会话提示仅依据所选模板或用户提供的方案。
- 模板声明每个阶段的输入材料、输出材料和步骤所需信息；字段区分必填、选填及允许明确填写未测定或不适用的情况。
- 数值应保留单位及信息来源。预设参数先展示，用户可逐项更正或集中确认所列操作条件与用量；实测结果不能由模板生成。
- 必需信息缺失时允许保存已确认事实和待补进度；未知不填零，不据此认定未执行步骤已完成或允许库存提交。
- 从中间进入时，前序阶段通过来源链接承接，不能自动标记为本次已执行。

### 暂停与完成的区别

输入暂停会完成本次已执行部分的记录收尾。模板各步骤仍保留真实状态：未做步骤转待办，缺数据列待补。

例如模板有三步，只做完前两步后暂停：本次已执行部分作为完成阶段保存；第三步仍未执行，保留在日历事项中。不能因暂停、归档或生成记录而把第三步改为已执行。若实际在模板未预设的暂停位置中断，只记录事实，不自动认定可以直接继续。

### 版本与兼容

- 旧模板支持普通记录，不自动推断阶段；预设参数同样需确认。
- 新模板按阶段规范设计，实验启动时固定模板内容及版本，跨会话继续不自动升级。
- 显式升级时展示阶段、字段映射及已有进度影响，确认后迁移，保留原版本依据。

## 实验与样品关系

- 同次实验暂停继续、补录或阶段重做沿用原编号。完整重复开展一次新实验另建编号。
- 模板声明产生新材料时，产物建立独立样品编号，关联来源样品、产生实验及阶段。普通取用沿用原身份，分装遵守既有分装规则。
- 各样品独立保存阶段和步骤进度，相同步骤可集中收集；部分样品继续或失败不改变其他样品进度。
- 允许接入来源历史不完整的旧样品或外部样品，已知信息如实记录，未知不补造。缺少必要库存信息或继续条件时仅暂停相关提交或后续提示，仍可保存独立进度。

## 会话、重做与更正

1. 进入实验时选择模板、已有实验或新实验及入口，读取对应样品与已保存状态。
2. 按步骤集中提示相关信息，接收自由文本和多步骤输入，仅追问缺失、冲突信息。
3. 确认阶段前汇总事实与具体库存变更，一次确认覆盖已展示内容。未知或未展示库存项不提交；记录与进度可以先保存。
4. 模板允许的分支由用户选择；超出模板的调整先展示确认，已发生的偏离照实记录。
5. 真实失败重做新增阶段尝试，保留此前操作、结果、样品和实际消耗；同一真实操作的技术重试不重复扣账。
6. 已保存事实更正保留前后内容和依据，展示影响范围再确认；相关下游内容待复核，真实已发生的操作保留。库存更正另列调整清单，不通过重新提交旧取用来修正。

## 日历接入与待办

### 首次安装

首次安装或手动复制后的首次初始化，由宿主会话询问目标日历服务及具体日历，复用已有连接或安装、连接对应插件／MCP，完成必要的用户登录与授权。项目不预先绑定 Outlook 或其他特定服务。

本地安装脚本负责初始化和报告日历配置状态，宿主会话负责交互及插件／MCP 接入。服务名称、目标日历和事项映射可记入项目配置或内部状态；认证凭据由宿主连接管理。

### 排期与更新

- 暂停先保存阶段事实。缺少后续排期时集中询问日期、开始时间和预计时长，已有信息不重复询问；齐全后直接写入选定日历。
- 按每个后续阶段创建一条事项，正文包含剩余步骤、样品编号和实验记录位置。日期按项目时区解释，默认使用 Asia/Shanghai，并由适配器转换为服务要求的时间格式。
- 同一待办保存稳定标识及远端事项标识，重试、恢复或再次暂停更新同一事项，避免重复创建。
- 继续后更新剩余内容，用户手工调整的排期保留。事项中全部实际工作完成后增加已完成标识并保留历史；暂停产生的未做部分不能因此自动标完。
- 用户在日历中修改计划不等于已执行实验，不据此写入实际操作或扣减库存。
- 未提供日期、未完成连接或远端写入失败时，保留内部待同步信息并说明状态；恢复后再同步，不声称已经排期成功。
- 不另建用户维护的待办.md；内部步骤与同步元信息用于恢复、防重复和定位远端事项。

## 实验结束、结果整理与归档

明确提交本次最终结果后，整理当前请求范围内的结果；必要内容未补齐时继续收集。结果已写入记录、附件关联完整后标记结果整理完成，并视为实验结束。

`completed`、`completed_at` 继续表示结果整理，不表示所有模板步骤均执行或实验成功。阶段进度和执行结束保存在内部状态；新增 `important` 表示整次实验的重要性，默认 false，可在结果输入或归档时指定，也可事后修改，与结果精选独立。

完成结果整理后自动执行实验记录归档检查，仍须有效记录、已完成的库存核查及可追溯证据。检查未通过时保留已达到的结束和整理状态，记录归档待处理；后续会话或工作流动作补齐条件时，沿用本次授权自动归档，无需重复归档指令。未完成待办继续保留。

上述自动行为由会话和工作流调用推进，不声称提供脱离宿主的后台监听。实验记录归档不等同于 OpenSpec 变更归档；Git 仍由用户主动提交。

## 建议实施结构

本节记录已确认的实现安排；本轮已据此完成实现，模块和验证见 v4 实施报告。

1. `assets/` 增加通用阶段模板及不含真实实验参数的结构示例，扩展记录模板的来源关联和重要属性说明。
2. `references/` 增加阶段模板设计规范、交互记录与日历接入说明，并同步修订旧的模板默认值、自动流程属性及归档规则。
3. `scripts/` 扩展模板解析、内容版本固定、样品来源、逐样品步骤进度、阶段尝试、更正影响及待归档检查；新增日历适配所需的配置和稳定事项映射。
4. 安装入口和首次使用入口引导日历选择与接入。能力不足时返回明确待办状态，不把宿主插件安装当作普通 Python 文件操作。
5. 主 SKILL.md 保持按需路由，普通记录不加载无关分析或完整技能库；日历能力仅在初始化、排期或事项更新时使用。
6. OpenSpec 配置需区分项目草稿的写入边界与用户明确触发的实验暂停、结果整理和自动归档授权，保留手动 Git 提交规则。

## 验收场景

- 从模板首阶段开始、任一声明入口继承旧样品，以及跨会话沿原编号继续。
- 中途暂停后只关闭已做部分，未做步骤进入日历，未知数据不补造。
- 多样品进度不同、部分失败重做、多个来源及阶段产物可追溯。
- 参数集中确认、实测数据来源、缺项保存、明确最终结果与普通讨论的区别。
- 库存清单授权、重试不重复消耗、事实更正与真实重做的区别。
- 首次安装日历选择、无时间排期追问、外部写入失败恢复、重试不重复创建及保留手工排期。
- 整理完成自动归档、检查失败后恢复、未完成待办保留及重要属性默认值。
- 旧模板普通模式、已有实验模板版本固定、显式升级及人工文件修改保护。
