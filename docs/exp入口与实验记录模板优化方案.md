# `$exp` 入口与实验记录模板优化方案

## 状态与范围

本文件记录设计访谈中已确定的方案，尚未授权实施。范围包括 `$exp` 入口、正式实验记录的模板结构、缺项问答和正文表达。细胞培养技能暂不独立，`cell-qpcr`、`qpcr-ddcq` 及细胞 qPCR 方法模板本轮不改。

## 已确认的决策

| 事项 | 决定 |
|---|---|
| 入口 | 仓库提供名为 `exp` 的薄入口技能；用户在对话中使用 `$exp` 显式进入主实验工作流。进入后，实验级子技能仍按实验类型与已确定方案激活。 |
| 安装 | 仓库交付入口；个人技能目录的安装属于后续部署，入口与主技能须能一起定位。 |
| 新记录格式 | 使用 `assets/experiment-record.template.md` 作为唯一结构来源，固定必需章节、子章节及顺序。 |
| 补充内容 | 归入相应必需章节下的附加小节；`## 上样计算` 是可选的顶层章节，位于实验方案之后、结果之前。 |
| 保存校验 | 校验标题、层级和顺序；各节正文可以为空。空白不转换为实测事实，不写模板占位符。 |
| 旧记录 | 编辑时保留原格式；只有用户明确要求迁移才转换为新模板。旧记录仍进行既有语义校验。 |
| qPCR | 本轮不修改 qPCR 技能及模板，也不创建细胞培养独立技能。 |
| 缺项交互 | 当前步骤的阻断性缺失值及冲突优先通过问答框集中处理；已有自由文本直接接收，不重复询问。可靠候选可供选择，否则开放输入，不猜测实验数据。 |
| 正文表达 | 单个数据值只显示已确认的值，不附带消息来源、取值过程或系统读取说明；必要的样本链接、来源实验、模板版本和计算依据仍保留。 |
| 相对时间 | “刚刚完成”等表达先按本次会话可获得的北京时间形成候选，在问答框确认或修改后写入；正式记录统一使用 `HH:mm`，不显示“约”。估计依据保留在内部状态。 |

## 已知事实

1. 主技能名称目前是 `experiment-workflow`，仓库与本机个人技能目录均未发现 `exp` 入口。（来源：`experiment-workflow/SKILL.md`、仓库及个人技能目录检查）
2. 正式记录模板包含元信息、基本信息表，以及“目的—实验方案（参考方案、实验方法）—结果—附件”结构。（来源：`experiment-workflow/assets/experiment-record.template.md`）
3. `stage_workflow.py` 新建记录时拼接了另一套简化骨架；`workflow.py` 保存时只检查部分章节是否存在，没有校验完整顺序和层级。（来源：`experiment-workflow/scripts/stage_workflow.py`、`workflow.py`）
4. `cell-qpcr` 当前仍包含细胞来源与处理登记、RNA、RT、qPCR 和结果交接阶段。（来源：`sub_skill/cell-qpcr/SKILL.md`、`references/stages.md`）
5. 当前规则要求集中追问缺项与冲突，阶段预览已有 `prompts`／`missing`，但没有规定统一使用问答框；阶段输入及保存状态有 `source`、用户原话和确认依据。（来源：`experiment-workflow/SKILL.md`、`references/stage-record-module.md`、`scripts/stage_templates.py`、`scripts/stage_workflow.py`）

## 实施设计

### 一、技能入口

1. 在仓库新增独立 `exp/SKILL.md`，名称为 `exp`，只负责明确进入现有主技能与传递本次用户意图，不复制主技能正文。
2. 将主技能的自动触发描述调整为由显式入口或明确直接调用进入；保留既有 `experiment-workflow` 名称供旧调用兼容。主技能进入后仍按现有条件定位实验级子技能。
3. 入口使用相对同级技能定位，并在安装说明中声明 `exp` 与 `experiment-workflow` 需一起部署，避免个人目录单独复制入口后引用失效。

### 二、模板生成与校验

1. 提取统一的记录结构读取与校验逻辑，供 `stage_workflow.py` 预览／保存及 `workflow.py` 显式记录写入复用。
2. 新记录从 `experiment-record.template.md` 生成：保留元信息与基本信息表，替换实验编号等占位符为已知值或空白。不得将模板说明文字当成实际实验事实。
3. 校验必需顶层章节及“参考方案／实验方法”子章节的名称、层级与顺序。允许对应章节内的附加小节，以及位于“实验方案”和“结果”之间的可选“上样计算”。
4. 内容完整性不作为此结构校验的保存门槛；空日期、空目的、空结果及空附件均可通过结构校验。其他既有的事实来源、编号一致性、历史留存及人工修改保护规则继续适用。
5. 对已存在的旧格式记录，默认沿用旧校验与原有排版。显式迁移时先预览结构转换及原文归属，按现有历史版本规则保存旧版。

### 三、验收情形

1. 用户在对话中调用 `$exp` 后进入主工作流；讨论备选实验不误激活具体实验级技能。
2. 新建记录的元信息、基本信息表、必需章节及子章节与模板一致；未提供的字段为空，正文没有 `{{...}}`、`TODO` 或虚构数据。
3. 调换章节顺序、改错标题层级或漏掉必需章节时，正式保存被拒绝并指出具体位置。
4. 有出处的附加小节和符合位置要求的“上样计算”通过结构校验。
5. 旧记录的普通编辑不触发自动转换；显式迁移保留原文与历史版本。
6. `cell-qpcr`、`qpcr-ddcq` 及现有细胞 qPCR 方法模板无变化。

### 四、缺项问答与正文简写

1. 阶段预览及普通记录整理时，先识别当前步骤的阻断性缺失值和互相矛盾的输入，将彼此独立的问题集中放入问答框；有前后依赖的问题分轮提出。已知数据不重问，非阻断性的空白沿用“允许空章节”的决定。
2. 若已有明确可核对的候选值，问答框给出选项和推荐值；实验测量值、数量、浓度等无法可靠预列时使用开放输入。用户继续以自由文本回答时同样接收，并重新核对剩余缺项。
3. 正式记录对每个字段只写所确认的实际值和必要单位，不在值后拼接“用户刚刚说”“按系统时间读取”等说明。内部状态继续保存用户原话、确认记录、时间读取和计算依据，供更正及审计使用。
4. 样本编号链接、来源实验与阶段、方法模板名称及版本、计算规则和输入等属于识别对象或复核计算所必需的结构化信息，按现有章节保留。上述要求只删除逐值的解释性文字，不删除这些关联。
5. 相对时间先读取本次会话可获得的北京时间并明确这是候选时刻，要求用户在问答框中确认或改写。确认后的正式记录只写 `HH:mm`，例如 `铺板完成时间｜14:55`；原话是否带“约”不改变该显示格式，估计性质只保存在内部依据。
6. 若宿主当时没有问答框能力，交互规则仍须以集中、编号的问题呈现并接收自由文本，不得因界面能力缺失而猜测值或静默保存冲突。

### 五、补充验收情形

1. 当前步骤缺少浓度及孔数时，能可靠提供的选项在问答框中选择，其余字段开放输入；已提交的字段不再询问。
2. “刚刚完成铺板”触发候选北京时间展示；用户确认 `14:55` 后，正文为 `铺板完成时间｜14:55`，没有消息时间或取值解释，内部能追溯本次确认。
3. 用户给出相互冲突的两个实际值时，问答框要求选择或更正；未解决前不把任一值写成既定事实。
4. 正文中的样本链接、来源实验、模板版本和上样计算依据仍可核对。

## 设计取舍

`$exp` 采用薄入口以避免复制主技能规则；正式记录只强制结构，因而允许在实验尚未获得结果时保存空章节。旧记录不自动重排，以免在缺乏事实来源的情况下改变既有记载。问答框负责取得或核对事实，正文负责简洁呈现事实，内部状态负责追溯；去掉正文中的逐值说明不等于免除核对。上述取舍均来自设计访谈，不构成对空白记录科学完整性的认可。
