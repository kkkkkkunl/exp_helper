## 第一轮回答（已确认）

1. 仅记录或附带数据不自动启动结果整理；明确要求分析、计算、绘图、整理结果时才启动对应模块。
2. 库存管理独立；每次记录模块完成后自动触发，不等待整个实验完成。也接受直接输入报废等库存指令，不主动询问是否需要手动管理库存。
3. completed 定义为结果整理完成；分析未完成不阻塞归档。

第三条取代先前“整套工作流完成”的语义。尚待明确：结果整理完成与分析完成之间的关系，以及纯记录归档时的属性组合。自动触发库存是否包含自动提交尚未确认，不能据此推断废除旧确认规则。

## 只读核查事实

- 当前单入口包括全部阶段说明；project.validate 会校验所有分析 skill，纯记录受到无关依赖影响。
- finalize 当前强制检查分析及库存状态，和新归档规则不一致，后续需修改。
- 补录当前会重置所有分析状态，未区分内容是否影响分析。
- project.dispatch 已支持名称→单个 SKILL.md 路径，无需读取所有正文。
- 在检查范围内未发现独立实验分析 skill 仓库；仓库位置与索引方案待确定。

## 第二轮回答（已确认）

- 结果整理完成与分析完成分开：本次要求整理的已有结果整理完成，可标记 completed；另有未分析文件不阻塞归档。纯过程记录不自动标 completed:true。
- 库存自动触发后，无变更直接结束；有推导变更生成清单并确认。用户直接给出信息完整的具体库存操作指令，可作为该操作授权，无需重复确认。
- 不使用固定绝对路径的共享仓库。分析 skill 仓库归属项目，安装主 skill 时自动建立对应目录，配置使用项目相对路径。

## 下一轮边界

- 名称索引更新、缺失名称与同名冲突的处理。
- 补录只影响记录时是否保留已有结果整理完成状态；数据/参数变化时如何失效。
- 分别表达结果整理、分析、归档状态的属性约定。

## 第三轮回答（已确认）

- 新增显式安装命令，项目内目录为 skills/experiment-workflow 和 skills/analysis，后者含 index.json 与各分析 skill 目录；手动复制安装时首次使用补齐缺失目录，保留已有配置和文件。
- 分析 skill 安装/更新时维护索引，日常按名称读取索引条目和目标正文。缺失名称保留记录并提示；同名冲突报错，不自动覆盖、下载或扫描全部正文。
- 仅补录日期或操作说明时，不撤销已有结果整理完成标记。涉及结果、相关输入或分析参数变化时，仅使受影响的任务失效。
- Obsidian 文档仅用 completed、completed_at 表示整理是否完成及完成时间；不新增 status、analysis_status、archived、archived_at 作为流程属性。已有标签和其他自定义属性保留。分析、归档及库存进度由内部状态文件保存。

## 待整体核对的实施方案

1. 精简 SKILL.md 为最小入口与路由；记录、结果整理、库存、安装维护各自按需读取说明。普通记录不读取结果整理说明，不校验无关分析 skill 的依赖。
2. 明确要求分析/计算/绘图/结果整理时才进入相应模块；附带数据本身不触发。按名称从项目内索引解析并加载目标 skill，不读取整个技能库正文。
3. 每次记录模块完成后自动进入库存处理；无变化直接结束，有推导变化生成清单确认；信息完整的直接库存指令作为该项授权，不重复确认，也不主动询问是否要手动管理库存。
4. 归档独立于分析完成，保留待分析任务。completed 仅表示本次要求整理的已有结果已整理完成，未请求结果整理的纯过程记录不自动设置 true。
5. 自动生成的流程属性只包含 completed 和 completed_at。未完成时 false/null，完成时 true/实际时间；不相关补录保留标记，相关变化清除对应完成状态。
6. 新增项目安装/初始化与分析 skill 安装/索引维护入口，全部配置使用相对项目根的路径，保持项目可迁移；不自动安装尚未提供的专门分析 skill。
7. 修改代码、说明和测试；兼容旧记录，更新自动管理字段时保护正文及自定义属性；重新打包并提供具体修改说明。
